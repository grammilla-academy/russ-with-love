## Исходники

- `content.json` — все тексты EN/IT/RU, включая переводы и фрагменты отзывов.
- `build.py` — генерирует HTML, sitemap и robots без зависимостей.
- `site.css` — общие адаптивные стили.
- `index.html`, `it/index.html`, `ru/index.html` — готовые страницы; английская версия в корне.
- `privacy.html`, `it/privacy.html`, `ru/privacy.html` — отдельное описание фактической работы сайта, не изменение политики приложения.
- `assets/` — оптимизированное фото, Open Graph и favicon.
- `prepare_images.py` — однократная оптимизация предоставленного фото; требует уже установленный Pillow.
- `validate.py` — проверка локальных ссылок, контента, SEO и изображений; требует Pillow.
- `originals/`, `qa/` — только локально, исключены из Git. Оригинальный PNG дополнительно сохранён в originals, исходные файлы пользователя не изменены.

Изменять content.json и site.css, затем выполнять:

```powershell
python build.py
python validate.py
python -m http.server 51423 --bind 127.0.0.1
```

Открыть http://127.0.0.1:51423/ и проверить EN, IT, RU, цены, письмо и мобильный экран. Письмо открывается в настроенном почтовом клиенте; сайт не отправляет его самостоятельно.

## Безопасное первое размещение на GitHub Pages

1. Войти в GitHub через Git Credential Manager; не передавать токены в чат или файлы. Проверить авторизованный аккаунт и права в grammilla-academy.
2. Снова проверить наличие `grammilla-academy/russ-with-love`. Если он существует, сначала клонировать/fetch и сверить содержимое; объединить изменения, сохранив удалённые правки.
3. Если отсутствует, создать отдельный публичный репозиторий `russ-with-love`, без изменения privacy и grammilla-support.
4. Поместить эти файлы в корень отдельного репозитория. Не публиковать originals, qa, токены или другие файлы из проекта приложения.
5. Использовать обычные commit/push, никаких force-push. В Settings → Pages выбрать Deploy from a branch → main → /(root). `.nojekyll` уже подготовлен. Обязательная сборка на сервере не нужна.
6. Дождаться успешного Pages deployment. Проверить публичные /, /it/, /ru/, изображения, privacy.html, sitemap.xml, canonical и языковые ссылки; полученный HTTP 200 с содержимым сайта, а не только принятую команду push.
7. Синхронизировать локальную копию с опубликованным commit и записать SHA и дату в этом README.
